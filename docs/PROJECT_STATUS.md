VOX отправляет стерео PCM S16_LE 48 кГц по UDP на порт 12345. Пакет SYN3 содержит 5 мс звука. Флаг `FLAG_LOW_LATENCY` включает прямой вывод на Станции для HDMI, а `FLAG_SESSION_RESET` запускает новую калибровку при смене источника. Станция отвечает телеметрией SAK2. На проверенном стенде управление задержкой ТВ выключено с обеих сторон.

## Автосинхронизация HDMI

- В начале звука или при смене источника Станция на короткое время освобождает ALSA и измеряет фактический звук динамиков ТВ своими микрофонами через `TODDR_A`. Для HDMI используется окно 420 мс. Сильный пик принимается сразу, умеренный требует подтверждения похожим пиком из другого окна. При старте в тишине возможна одна повторная попытка после появления достаточно громкого сигнала.
- Во время воспроизведения Станция оценивает задержку собственного выхода по петле `TODDR_B` и уточняет очередь на основе согласованных измерений. Поправка модели тракта ограничена 3 мс за один шаг. При неуверенном измерении состояние `HOLD` означает удержание предыдущей оценки. Поле `err=+0.0` само по себе синхронизацию не подтверждает.
- Прямой вывод HDMI использует `aplay -D hw:0,0 --buffer-size=1200 --period-size=240 -R 15000`. Это 25 мс буфера, 5 мс периода и 15 мс стартового порога. Компенсация расхождения темпа сохраняет дробный остаток сэмплов. `SoftVolume` масштабирует сигнал с коэффициентом от 0 до 1. Для обычного режима предусмотрен `default` через `dmix` 1920/480.
- Значение **44 мс** было результатом акустического замера в конкретном сеансе. Программа рассчитывает цель заново по звуку. При нехватке достоверного сигнала используется предыдущая или запасная цель.

## Сетевой сбой VOX и результат проверки

Wi‑Fi Direct на VOX примерно каждые 500 мс уводил радиомодуль на канал 11. Сетевой звук приходил пачками после пауз до 227 мс, хотя интервалы по меткам захвата не превышали примерно 20 мс. Это вызывало повторяющиеся опустошения буфера и волнообразный звук.

`wpa_cli -i p2p0 p2p_stop_find` вернул `OK`, но сетевые паузы остались. `wpa_cli -i p2p0 p2p_ext_listen` **без аргументов** отключил периодическое прослушивание Wi‑Fi Direct. После этого максимальный интервал поступления пакетов составил 22,4 мс в контрольном замере 3745 последовательных пар. VOX остался подключён к роутеру, HDMI2 продолжил работать. Команда изменила состояние текущего сеанса. После перезапуска ТВ проверку нужно повторить. Изменение автозапуска VOX в код проекта не входит.

## Повторное эхо после долгой игры

После сетевого исправления регулятор в режиме HDMI принял повторяющийся пик в записи, где одновременно звучали ТВ и Станция. Из-за этого цель выросла до 81 мс. В этот момент 20-секундный замер не выявил потерь пакетов, цифрового клиппинга на входе или новых XRUN. Отдельный замер при молчащей Станции показал 44,92 мс для ТВ.

Исправленный контроллер удерживает последнюю цель, полученную при чистом измерении динамиков ТВ. Согласующиеся смешанные оценки теперь могут запросить повторный чистый замер. Они сами не меняют цель. Между такими запросами действует пауза не менее двух минут. Если повторный замер не подтверждается, сохраняется предыдущая цель.

После установки Станция самостоятельно измерила на HDMI2 48,76 мс и выставила цель 50 мс. Пользователь подтвердил, что эхо исчезло. Значение вычислено из звука текущего источника и не записано как профиль PS5. Причина ранее слышимого скрипа отдельно не подтверждена.

## Возврат в YouTube и резкие щелчки, 20 ноября

После перезапуска VOX вновь появились паузы до 258 мс из-за фонового Wi‑Fi Direct. Паузы совпали с опустошением ALSA и отбрасыванием кадров. На VOX остановлено периодическое прослушивание и установлена однократная проверка при загрузке `/var/lib/webosbrew/init.d/81-vox-audio-wifi`. Её действие подтверждено без перезагрузки. После следующего запуска проверить `/tmp/vox-audio-wifi.log`. Фоновое обнаружение для беспроводного дублирования может быть недоступно.

На Станции повторный чистый акустический замер теперь работает и для YouTube, если первоначальная попытка не удалась и появился устойчивый звук. Во время пропуска кадров и провала ALSA сглаживаются резкие переходы в пределах 2 мс, без добавления кадра. Пользователь подтвердил синхронизацию после перехода через главную страницу VOX и чистый звук в проверочном отрезке. Итоговая сборка за первые 40 секунд обработала 8 001 пакет с нулевым приростом потерь, отброшенных кадров и XRUN.

## С чего продолжать

1. Уточнить источник, режим ТВ и слышимый симптом. Для эха нужен повторяемый отрывок игры с отчётливыми звуками и оценка на месте прослушивания. Для хрипов сначала проверить сеть и прирост XRUN за один и тот же отрезок. `starv` в прямом режиме считает ожидания пакетов, а `xrun` — реальные опустошения ALSA.
2. Прочитать журналы и сравнить установленный бинарник с проверенной сборкой. [`doctor.sh`](../doctor.sh) читает состояние обоих устройств. На Станции искать `CLEAN_LOCKED`, `[acoustic-sync]`, `max_rx_gap_ms`, `loss`, `drop`, `xrun`. На VOX смотреть `/tmp/vox_sender.log` и в журнале ядра искать `ro_ch_handler(p2p0)`. По одному числу `lst` вывод о рассинхронизации не делать.
3. Если после перезагрузки VOX снова появились интервалы порядка 200 мс, сопоставить их с Wi‑Fi Direct. Остановку фонового прослушивания на ТВ повторять только с согласия владельца, особенно во время игры или трансляции. Увеличение буфера Станции до размера сетевой паузы скрывает часть провалов ценой заметной задержки.
4. Для разработки начинать с [`acoustic_sync.go`](../station-daemon/acoustic_sync.go), [`controller.go`](../station-daemon/controller.go) и [`main.go`](../station-daemon/main.go). Проверки локально: `(cd station-daemon && go test ./... && go vet ./...)` и `(cd webos-sender && python3 -m unittest)`. Для изменения только приёмника использовать сборку и развёртывание из `station-daemon/`. [`deploy-webos.sh`](../deploy-webos.sh) затрагивает ТВ и Станцию, поэтому для диагностики во время игры его не запускать.
5. Точка возврата исходного v3.2 — `42e9e1d`. Перед развёртыванием сохранить установленный бинарник и параметры. Временные копии на устройствах могут исчезнуть после их перезагрузки. Полный `rollback.sh` затрагивает обе стороны, перед запуском нужно проверить область отката.

В Git хранятся исходники и документация. SSH-ключи, учётные данные и необработанные записи аудио в репозиторий не добавлять.
